# UX/UI guide — Sentinel Explorer Web

## 1. Характер продукта
Это рабочая ГИС, а не декоративная аналитическая панель. Главная площадь — карта. Визуальный язык единый для лендинга и приложения: мягкая холодная графитово-сине-серая основа, приглушённые голубые акценты и редкие лавандовые оттенки. Зелёный не используется в UI. Цвета интерфейса не должны путаться с цветом геоданных.

## 2. Desktop layout
1. Верхняя панель: логотип, режим, основные действия, статус сети, настройки.
2. Левая компактная панель: Поиск, Слои, Измерения и локальные данные по мере появления.
3. Центральная карта: основной рабочий холст, масштаб, координаты, AOI.
4. Правая рабочая панель: активный контекст — поиск, результаты, RGB или свойства сцены.
5. Статусная строка: координаты, масштаб, источник, состояние загрузки, CRS при необходимости.

Не открывать все панели сразу. Одна активная рабочая панель, остальные вызываются через навигацию.

## 3. Scene card
Показывать дату/время и timezone, platform если доступна, облачность или «нет данных», полный ID по запросу, footprint, фактическую доступность B02/B03/B04/B08, provider и состояние. Thumbnail допустим только если он реально получен. Не придумывать metadata.

## 4. Search panel
- AOI: текущий viewport, прямоугольник или bbox.
- date from/date to.
- cloud cover max 0–100.
- продукт MVP — Sentinel-2 L2A.
- явная кнопка «Найти сцены».
- reset.
Поиск не должен автоматически отправляться при каждом pan карты. Режим поиска по перемещению — позже, выключен по умолчанию.

Показывать loading, empty, error, partial и pagination отдельно.

## 5. RGB panel
Три независимых selector:
- R: B02/B03/B04/B08;
- G: B02/B03/B04/B08;
- B: B02/B03/B04/B08.

Повторный выбор канала в нескольких слотах допустим, если обработчик его поддерживает. Выбранная композиция всегда явно отображается.

Следующие настройки: percentile/manual stretch, min/max или percentiles, gamma, reset, opacity. Пока нет статистики, показать «получаем статистику» или ошибку, а не ложное успешное состояние.

## 6. States
- Loading: показывать фактическое действие; проценты только если backend их измеряет.
- Empty: сообщать, что поиск завершился без результатов; предложить изменить фильтры.
- Error: короткая безопасная причина и request ID; не показывать stack trace, токены и внутренние адреса.
- Partial: ясно показывать, какие providers дали результат и какие недоступны.
- Offline: различать отсутствие сети, недоступность backend, upstream provider, наличие локального cache.

## 7. Responsive
Desktop: карта и панели одновременно.
Tablet: правая панель — drawer.
Mobile: карта основная, инструменты доступны в компактной панели/bottom sheet. Не прятать основное управление за hover. Касание должно работать.

## 8. Design tokens
Единая палитра для лендинга и приложения (CSS variables в обоих entrypoints): background #171C26, background-deep #111620, surface #202735, surface-raised #293445, border #3A4658, text #E8EDF5, muted #AAB6C7, primary #A9C5E4, primary-strong #8EAED2, secondary #C1B5D8, info #AFC4DE, warning #D8C7A4. Error использует отдельный приглушённый красный. Не использовать зелёные оттенки в элементах UI. Цвета спутниковых растров, векторных тематических слоёв и пользовательских данных остаются независимыми от темы.

## 9. Accessibility
- Кнопки имеют доступные имена.
- Видимый keyboard focus.
- Панели доступны клавиатурой.
- Статус не кодируется только цветом.
- prefers-reduced-motion.
- Контраст текстов и control states проверяется.
- Критические операции не требуют исключительно мыши.

## 10. Запреты
- Не использовать фальшивый satellite image как реальные данные сцены.
- Не имитировать загрузку или прогресс.
- Не показывать выдуманную cloud cover/statistics.
- Не закрывать карту декоративными панелями.
- Не делать панель чрезмерно широкой.
- Не использовать тяжёлую анимацию на слабом железе.
