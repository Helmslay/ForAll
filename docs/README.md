## Порядок чтения
1. [AI_WORKFLOW.md](AI_WORKFLOW.md) — обязательные правила работы ИИ.
2. [EXECUTION_PLAN.md](EXECUTION_PLAN.md) — индекс этапов, зависимостей и задач.
3. Файл соответствующей фазы в tasks/ — подробная карточка задачи.
4. Документ конкретного модуля — архитектура, API, UX, данные, тесты или развёртывание.

## Статусы
- PLANNED — запланировано.
- READY — зависимости выполнены, карточка готова.
- IN_PROGRESS — выполняется.
- IN_REVIEW — код написан, критерии ещё не проверены.
- DONE — все критерии приёмки пройдены.
- BLOCKED — внешняя блокировка с описанной причиной.

Не переводить задачу в DONE только потому, что модель сгенерировала код.

## Принципы
- Сначала доказать доступность источников и файлов из России, затем писать загрузчик.
- Браузер обращается к собственному backend; секреты поставщиков не попадают в браузер.
- Каталоги подключаются адаптерами; UI не зависит от поставщика.
- MVP: Sentinel-2 L2A, каналы B02, B03, B04, B08.
- Любой из четырёх каналов назначается на R, G и B независимо.
- В production нельзя подменять реальные данные фиктивными.
- Большие операции выполняются фоновыми заданиями.
- Начальная архитектура — модульный монолит.
- Россия без VPN — критерий приёмки, не обещание до тестирования.

## Разрешение противоречий
Если документы, существующий код и задача расходятся: проверить фактический код; зафиксировать расхождение; предложить правку; не менять публичный контракт молча.

Наличие ссылки на API не доказывает доступность сервиса из России. Перед реализацией проверять актуальные спецификации и условия использования источников.
