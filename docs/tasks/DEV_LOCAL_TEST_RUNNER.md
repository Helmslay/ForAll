# DEV-00.01 — локальный Windows Runner для автоматических тестов

**Статус:** IN_PROGRESS  
**Зависимости:** WEB-00.02 — DONE  
**Цель:** запускать существующие offline unit tests на доверенном Windows-компьютере через GitHub Actions без ручного запуска команд при каждой проверке.

## Scope
- Workflow `.github/workflows/windows-local-tests.yml`.
- Инструкция регистрации self-hosted runner в `tools/README.md`.
- Никаких изменений production-кода и сетевых проверок провайдеров.

## Безопасность
- Репозиторий публичный: не добавлять триггер `pull_request` и не запускать код из fork/PR на личном компьютере.
- Workflow выполняется только для `main`; ручной запуск — только из доверенной ветки `main`.
- Минимальные права workflow: `contents: read`.
- Checkout не сохраняет GitHub credentials.
- Использовать отдельную стандартную учётную запись Windows с минимальными правами; не давать runner доступ к личным файлам, браузерным профилям, SSH-ключам и секретам.
- Регистрационный токен runner временный. Не публиковать и не передавать его в чат.

## Проверки workflow
- Python 3.12 устанавливается action автоматически.
- Выполняется `python -m unittest discover -s tools -p "test_*.py" -v`.
- Выполняется `python -m py_compile tools/check_stac.py tools/test_check_stac.py`.
- Workflow запускается при изменениях в `tools/**` на `main` или вручную из `main`.
- Нет триггера для Pull Request.

## Критерии приёмки
1. Workflow находится в репозитории и ограничен доверенной веткой `main`.
2. Windows x64 runner зарегистрирован с меткой `sentinel-local`.
3. Первый запуск на компьютере пользователя завершился успешно; в логе видны все unit tests и шаг компиляции.
4. Секреты и регистрационный токен не попали в репозиторий или логи.

## Порядок регистрации компьютера
1. Открыть GitHub → репозиторий ForAll → Settings → Actions → Runners → New self-hosted runner.
2. Выбрать Windows и x64.
3. Выполнить показанные GitHub одноразовые команды настройки, добавив пользовательскую метку `sentinel-local` (или указав её в команде конфигурации).
4. Настроить runner как службу под отдельной стандартной Windows-учётной записью. Если это пока невозможно, запускать runner вручную только на время тестов.
5. Убедиться, что runner отображается как Idle/Online, затем запустить workflow из Actions на ветке `main`.

**Не передавать в чат:** временный registration token, содержимое файлов credentials и любые секреты.

- Реальный запуск на компьютере пользователя ещё не подтверждён.
